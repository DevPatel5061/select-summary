## What is active and must stay

Every runtime file has a manifest, HTML/module import, local template fetch or worker injection path. No entire runtime file was confirmed abandoned. There is no database, server-route layer, runtime dependency manifest or third-party runtime dependency to prune.

- `bootstrap.js` and `interface.html` share dashboard markup between toolbar and standalone views. Their bundled local fetch is intentional, not a remote API call.
- `summary-card.js` works both as an injected classic script and side-effect module. Its global guard, shadow DOM and separate CSS are intentional. `content.js` is injected dynamically, so static manifest scans alone can falsely label it unused.
- Popup key replacement, confirmation dialogs, notices, copy feedback, history empty states and the shared summary card have live callers. No unused standalone UI component was confirmed beyond removed onboarding control styles and icon paths.
- Persistent version-3 and legacy key/history migrations protect user data. Destructuring obsolete state properties out of migrated objects is deliberate, not an unused-variable deletion candidate.
- The storage queue, credential revisions, sender/input validation, request IDs and in-flight guards protect real concurrency/security boundaries. Do not remove them as complexity reduction.
- Provider verification and each explicit summary make one request. No redundant automatic Gemini request was identified. `storage.js` performs serialized local storage reads/updates; there are no SQL queries or backend database calls.

## Ordered cleanup plan

1. Land verified dead-code removal, shared normalization/keycap logic, session gating and tests with accurate docs.
2. Consolidate onboarding CSS with computed-style/screenshot checks; preserve the current grid and keep popup/card appearance unchanged.
3. Optimize popup refresh granularity, then extract shared transport and field behavior with key-replacement and focus tests.
4. Simplify provider helper boundaries; retire old persistent fields only through an explicit migration plan.
5. Archive development artifacts after choosing which references to retain. Exclude them from release packages.

## Validation and limits

`node --test tests/onboarding.test.mjs` uses mocked Chrome storage/messages and provider responses. It checks denied Ready/Finish before practice, failed summaries, successful summaries, replay reset, preserved key/history, stale-run rejection, tab isolation and late-response isolation. Browser checks use isolated profiles and simulated API responses for loops, placement, shortcuts, fresh replay, reduced motion and overflow. Live provider eligibility, native toolbar pinning and Web Store packaging remain manual checks. Follow-up recommendations above have not been implemented or benchmarked.
